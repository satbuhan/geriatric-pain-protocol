# Pharmacological Pain Management in Elderly Patients

An interactive, referenced walkthrough of the stepwise pharmacological pain-management decision
algorithm for patients aged 65 and older — from initial pain assessment and red-flag exclusion,
through severity-tiered drug selection (mild / moderate / severe), mandatory reassessment and
opioid-specific adverse-effect monitoring, to renal/hepatic/cognitive-impairment caveats and the
closing core prescribing principles. Every box in the diagram can be selected to reveal, in one
place: what the step means, why the algorithm calls for it, and the sources behind it.

**Live site:** https://satbuhan.github.io/geriatric-pain-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why*, and a reader outside
the authors' own team cannot easily check the evidence behind a specific box (why the figure's
own morphine box says "reduce dose" at the exact renal threshold where its own renal-impairment
box says "avoid"; why the figure lists a scale — VRS — that the source manuscript's prose never
mentions; why a drug the manuscript places under "agents to avoid in the elderly" still appears
in the figure as a usable option). This page keeps the original algorithm exactly as authored,
and attaches the clinical reasoning, the manuscript's own internal tensions, and the literature
to each box without cluttering the diagram itself.

The algorithm this page presents is Figure 1 of "Use of analgesics in older individuals:
Pitfalls and caveats" — an unpublished, blinded manuscript submission (2026) formatted for *BMJ*,
drawing on a systematic literature search (2015–2026, six databases, RCTs) on the clinical
efficacy and safety of analgesics in elderly patients in the acute setting — from a standalone
one-page figure PDF supplied directly by the authors, cross-checked against the figure as
embedded in the manuscript's own Section 5.C.

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Source workflow note:** same external-AI condensation path as `cwa-blood-gas-protocol`,
  `ccb-toxicity-protocol` and `haloperidol-adjunct-protocol` — the manuscript was run through an
  external AI (Gemini) using this project's structured condensation prompt
  (`tools/gemini-condensation-prompt.md` in the hub repo), producing a box-by-box breakdown
  already annotated with `[DISCREPANCY / AMBIGUITY NOTE]` and `[EXTERNAL GUIDELINE FLAG]` tags
  documenting every tension between the figure's exact box text and the manuscript's own
  prose/tables. This tool was built from that condensed document plus the authors' own
  standalone Figure 1 PDF. Those tensions are preserved in each affected node's "Cautions &
  special populations" section rather than silently resolved — including a direct
  self-contradiction the source material itself flags: the Morphine box says "reduce dose if
  eGFR <30" while the Renal impairment box says "Avoid morphine" at the same threshold, in the
  same figure.
- **Reference verification — explicit, author-granted exception (the fourth in this atlas):** by
  the author's own explicit instruction for this tool — *"yıne kendıne yuk etme. gemoınının
  dogrulamalarını kabul et. gucumuzu ıdarelı kullanalım"* — the 52-entry bibliography was **not**
  independently re-verified against primary sources. Dr. Karcıoğlu and the Gemini condensation
  pass have already evaluated the manuscript's references, so this build's own effort was kept
  to engineering the tool rather than re-checking citations — see `assets/content.js`'s header
  comment and `METHODOLOGY.md` for the full precedent record (alongside
  `epinephrine-revisited-protocol`, `ketamine-indications-protocol` and
  `haloperidol-adjunct-protocol`, the three prior tools with this same kind of exception). Every
  reference's `kind` field says so plainly: "As cited in the manuscript; not independently
  re-verified."
- **Rendering note — the uneven three-way branch:** the figure's Step 3 fans out into Mild /
  Moderate / Severe columns of unequal length (Mild has two boxes, Moderate and Severe have
  three each). Each severity-branch row is its own `LAYOUT` group (rather than one group reused
  across rows, which this atlas's rendering engine does not support — see `METHODOLOGY.md`), and
  the shorter Mild column simply has nothing in the row where Moderate/Severe continue, with
  Moderate's and Severe's boxes pinned to their own explicit grid column so they don't shift left
  to fill the gap.

## Disclaimer

This is an academic / educational reference tool, not a substitute for institutional protocol
or bedside clinical judgement. Doses shown reflect the algorithm as authored; verify against
current local protocol before clinical use. This tool's reference list is reproduced directly
from the source manuscript's own bibliography and was not independently re-verified for this
build — see Status above.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site that GitHub Pages can
serve directly.

```
index.html          page structure — masthead, the diagram (assessment trunk, the Step 3
                     three-way severity fan-out, the reassessment/ADR-monitoring trunk, the
                     Step 6 three-way organ/cognitive fan-out, the closing principles banner),
                     readout panel, references, abbreviation legend, footer
assets/style.css     design (the "paper" masthead/references, the diagram grid and its
                     3-wide fan-outs)
assets/content.js    ← single source of truth for every node's text and reference list. Edit
                     this file to change what the page says.
assets/app.js        rendering + interaction (builds the diagram and its connector lines from
                     content.js, handles the click-to-expand panel on desktop and the bottom
                     sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box from the diagram (`meaning`,
`rationale`, optional `dose`/`cautions`, and `refs` pointing at numbered entries in
`REFERENCES`). Add or edit a reference in `REFERENCES` and point to it by `id` from any node.
Never change a node's `label` or `sub` text without the author team's sign-off — those fields
are the algorithm itself, transcribed verbatim from the authors' standalone figure PDF.
